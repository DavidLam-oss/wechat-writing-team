# Routine: Sprout

## 目标

把外部素材加工成可被 `wechat-writer` Stage 1 稳定吸收的结构化 Seed。

`Sprout` 不是写文章，也不是定文风。它只负责把外部人物、事件、故事变成可用材料。

## 输入分类

在处理前，先把输入归为以下一种：

| 类型 | 说明 | 动作 |
| :--- | :--- | :--- |
| `person` | 有明确人物、身份和动作 | 通过 |
| `event` | 有明确时间、地点、当事人、结果 | 通过 |
| `story` | 有叙事弧线和人物 stakes | 通过 |
| `concept` | 抽象概念，没有具体抓手 | 拦截 |
| `trend` | 热点或趋势，但没有具体人物/事件 | **有条件放行**（见下「trend 通道」） |

## 拦截规则（concept）

如果输入是 `concept`：

1. 不要直接写 Seed。
2. 先追问，把它落到具体的人、事、故事上。
3. 优先追问：
   - 这个话题背后是谁？
   - 谁因此受益或受损？
   - 有没有一个具体案例？
   - 你第一次对这个话题有感受，是因为哪件事？

## trend 通道：热点嫁接四问

> **判据来源**：`knowledge/account_positioning.md` §7。这是**唯一判据**，不得在此另立一份。
> **历史行为**：`trend` 一律拦截。**现改为**「四问全过 → 降级为 `event` / `story` 放行；否则仍拦截」。
> 目的：热点不再走到门口就被挡回，而是「有抓手就放行、只有概念就挡回」。

### 第一步 · 归属检查

这条热点落在 `account_positioning.md` §4 的哪一块？

- 落不到 A–D 任何一块，**也不属于「个人与思考」** → **拦截**（不进入后续）
- 属于「个人与思考」 → **拦截**（该标签组不参与热点嫁接，唯一例外见 §7）

### 第二步 · 四问追问（四问全过才放行）

1. **落在哪块支柱上？**（承上）
2. **我有没有「上手 / 亲历」的抓手？** —— 没有 → 降级为观察素材（可入素材库），**不写**
3. **能不能给出「读者今天就能做的一件事」？** —— 不能 → 降级，不进选题池
4. **会不会为了蹭热点而扭曲标题？** —— 会 → **弃稿**

### 第三步 · 降级放行

四问全过 → **必须把 `trend` 降级为 `event` 或 `story`**，再走下面的正常 Seed 流程：

- `event`：能补出明确时间、当事人、结果
- `story`：能补出叙事弧线与 stakes

**硬门禁**：**榜单标题原样当选题 = 不合格**。必须先转成「我拿它做了什么」，再写 Seed。

- ✅ `Agent = Model + Harness：DeepSeek 把模型的「壳」开源了`（借事件讲清一个概念）
- ❌ `XX 发布，我第一时间体验`（主体是新闻，不是我的动作）

## HKR 选题质检（补充判断）

在完成上述拦截判断后，还需用 HKR 模型评估素材是否具备基本质量：

- **H (Happy)**：有趣/有悬念吗？能让读者产生"然后呢？"的冲动吗？
- **K (Knowledge)**：有信息量吗？读者看完能学到新东西吗？
- **R (Resonance)**：有情绪共鸣吗？能让人"对对对我也这么想"吗？

**及格线**：至少占两项。若素材明显只占一项或一项都没有，主动与用户沟通调整方向。

> 这不改变 Seed 的分类职责（person/event/story vs concept/trend），而是在通过分类之后，对素材质量做进一步的激活判断。

## Seed 生成要求

生成的 `Seed_[Topic].md` 必须包含：

1. 一句话洞察
2. 核心对象
3. 事实与来源
4. 外部案例
5. 反方视角
6. 第一性问题
7. 可嫁接到 David 经验的点
8. 可写方向
9. 相关旧文

格式和写法优先参考：

`references/template_seed.md`

## 项目绑定

在写 Seed 之前，先确定它属于哪个项目：

1. 如果当前已经在某个 `Project_[Title]` 工作，直接绑定到该项目。
2. 如果是独立触发 `/sprout`：
   - 优先读取 `project`
   - 没有 `project` 时，允许读取 `title` 作为目标项目标题
3. 如果目标项目不存在，先创建项目目录和 `_source/Seeds/`。
4. 如果既没有当前项目，也没有 `project/title`，暂停并向用户索取项目标题。

默认不允许 projectless Seed。

## 输出规则

默认输出到：

`articles/Project_[Title]/_source/Seeds/Seed_[Topic].md`

只有满足下列条件，才晋升到长期 Seed：

1. 后续多个项目都可能复用
2. 不是临时热点的短效噪音
3. 与 David 既有选题方向存在稳定连接

## 风格边界

`Sprout` 允许：

- 补事实
- 补案例
- 补对立面
- 补问题意识

`Sprout` 禁止：

- 代写正文
- 模仿别的人格文风
- 虚构 David 的经历、情绪或观点
